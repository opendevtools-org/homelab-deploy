# Site instance — start (product)

Refreshed from `upstream/` by `Update-HomelabUpstream`. Do not edit this file;
site notes stay in `README.md` (not overwritten).

`--project-directory .` so volumes hit this folder’s `data/`.

`docker-compose.custom.yml` is required: it mounts site `cli/` and `scriptkit/`
into PKM. Without that `-f`, those trees are not in the container.

Site CLIs belong only under `cli/custom/<name>/`. `cli/lib` and `cli/homelab`
are product code.

## Backend

```bash
docker compose --project-directory . \
  -f upstream/docker-compose.backend.yml \
  -f upstream/docker-compose.lan.yml \
  -f docker-compose.config.yml \
  -f docker-compose.custom.yml \
  -f docker-compose.apps.yml up -d
```

Localhost: use `upstream/docker-compose.local.yml` instead of `lan`.

Remove the one-shot init container (PKM data is kept):

```bash
docker compose --project-directory . \
  -f upstream/docker-compose.backend.yml \
  -f upstream/docker-compose.lan.yml \
  -f docker-compose.config.yml \
  -f docker-compose.custom.yml \
  -f docker-compose.apps.yml \
  rm --force --stop pkm-data-permissions site-cli-volumes-permissions
```

## Frontend

```bash
docker compose --project-directory . \
  -f upstream/docker-compose.frontend.yml \
  -f upstream/docker-compose.frontend.lan.yml up -d
```

LAN HTTPS (clipboard paste): add `-f docker-compose.https.yml` when
`HUB_HOSTNAME` and `PKM_HOSTNAME` are set in `.env`.

Do not combine backend and frontend `-f` files in one `up`.

## First start on a new host

1. `git submodule update --init --recursive upstream`
2. Copy `.env.example` to `.env` and set `PLATFORM_SERVICE_TOKEN`, `HUB_JWT_SECRET`, `JWT_SECRET`.
3. If Compose reports a name conflict, remove leftovers then `up` again:

```bash
docker rm -f home-hub home-hub-platform pkm-backend pkm-frontend
```
